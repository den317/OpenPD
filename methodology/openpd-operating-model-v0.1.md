# OpenPD Operating Model v0.1

## 1. Purpose

OpenPD treats professional development as an adaptive decision problem under uncertainty.

The objective is not to predict a complete career path. The objective is to improve the quality of professional decisions by combining bounded hypotheses, real-world probes, explicit evidence, and inspect/adapt cycles.

Canonical loop:

```text
current professional state
→ professional pressure / opportunity
→ 1–3 direction hypotheses
→ key uncertainty
→ one primary development bet
→ minimum useful evidence-producing probe set
→ real work / reality
→ evidence
→ inspect
→ adapt
→ next bounded bet
```

Optimization target:

```text
maximum decision-relevant learning
per unit of time / energy / money / commitment
```

## 2. Non-goals

OpenPD does not optimize for:

- a detailed 3–5-year roadmap under material uncertainty;
- maximizing the number of roles, courses, certifications, or tools explored;
- continuous profile rewriting from conversational impressions;
- treating every dissatisfaction as a capability gap;
- turning every experiment into capability proof;
- forcing all professions into one ontology;
- replacing profession-specific expertise with a generic career framework.

## 3. Core objects

### Professional state

The current evidence-backed description of the person's relevant professional situation. It may include demonstrated capabilities, important unknowns, role context, constraints, and current commitments.

### Direction hypothesis

A plausible, decision-relevant statement about a future professional direction or role configuration. A hypothesis is not a commitment or forecast.

Maintain at most three active direction hypotheses. Prefer one primary hypothesis and zero to two materially different alternatives.

### Key uncertainty

The smallest unresolved question whose answer could materially change which hypothesis or action is preferred.

### Development bet

A bounded commitment intended to improve professional position or reduce a material uncertainty. Maintain one primary development bet at a time by default.

### Probe

A cheap, bounded real-world action designed to produce evidence. A probe should discriminate hypotheses or resolve a material unknown more cheaply than a large commitment.

### Evidence

An observable result relevant to a claim, hypothesis, gap, or bet. Evidence records what happened and at what scope; interpretation is kept separate.

### Inspection

A deliberate review boundary at which observed facts are compared with preregistered criteria and hypotheses/bets are updated.

## 4. Evidence discipline

Preserve:

```text
source != claim != evidence != inference
trend != personal relevance != gap != action
unknown != false
absence of evidence != weakness
current-scope evidence != future-scope proof
unproven-at-required-scope != demonstrated deficiency
experiment != capability proof
model inference != external evidence
```

Professional state should change because evidence or explicit user correction warrants it, not because a model generated a plausible narrative.

## 5. From external pressure to action

When responding to a new trend, tool, certification, or role signal, use:

```text
external relevance
→ intended-work relevance
→ evidenced gap or important UNKNOWN
→ intervention
```

Possible decisions:

- `IGNORE` — no meaningful relevance now;
- `WATCH` — potentially relevant, evidence insufficient;
- `LEARN` — knowledge acquisition is justified;
- `EXPERIMENT` — direct practice can resolve uncertainty more cheaply;
- `ADOPT` — evidence is strong enough to make the practice part of normal work.

Prefer `EXPERIMENT` when direct practice can answer the question more cheaply than formal learning.

## 6. Probe design

Before a material probe record:

- active H1/H2/H3;
- key uncertainty;
- action;
- time cap;
- money cap;
- energy/attention cap;
- organizational commitment cap when relevant;
- expected evidence;
- what would strengthen each hypothesis;
- what would weaken each hypothesis;
- inspection date or inspection condition.

Canonical rule:

> Use the minimum set of cheap evidence-producing probes that can realistically be executed now.

One probe that discriminates several hypotheses is usually better than several parallel initiatives.

## 7. Inspection protocol

Inspection starts from observed facts, not from the previous plan:

```text
done
→ observed result
→ metrics / evidence
→ surprises / constraints
→ preregistered criteria
→ update hypotheses / gaps
→ next bounded bet
```

For every active hypothesis choose:

- `STRENGTHEN`;
- `KEEP`;
- `WEAKEN`;
- `DROP`.

A failed probe is useful when it reduces uncertainty. A successful probe proves only what its scope supports.

## 8. Diagnose before prescribing learning

When a professional problem appears, distinguish at least:

- capability problem;
- role-design problem;
- work-system problem;
- strategic constraint;
- sustainability constraint.

Do not solve every dissatisfaction with training.

## 9. High-commitment decisions

Before recommending a substantial course, certification, role change, or long project, inspect total-system cost when material:

- workload;
- time;
- energy;
- sustainability;
- financial/family constraints;
- opportunity cost;
- organizational commitment.

When a cheaper probe could materially change the decision, run the probe first.

## 10. Methodology status

Version 0.1 is intentionally experimental.

The first important validation is **cross-profession portability**: whether this operating loop remains useful for materially different professions without importing one profession's ontology or assumptions into the core.

Methodology change rule:

```text
recurrent defect
→ evidence
→ cause hypothesis
→ protocol change
→ expected effect
→ validation in subsequent cycles
```

Preserve prior versions and their historical semantics.
